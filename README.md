# Techunico Node Framework

Fastify 5 + TypeScript backend framework and the CLI that generates applications from it,
published as [`@techunico/node-framework`](packages/create-techunico-app).

```bash
npx @techunico/node-framework my-api            # interactive
npx @techunico/node-framework my-api --db mongodb --plugins redis,cache --yes
```

## How it fits together

There is no separate runtime package: the framework source in `src/` **is** the application
template. The CLI copies it into each new application, keeps only the selected database and
plugins, and installs only their packages. Generated applications own their copy of the code.

```text
src/                          framework + template source (what generated apps contain)
├── app.ts, server.ts         buildApp({ config }) and the entry point
├── config/                   env schema (core settings) and loadConfig()
├── core/                     JWT, auth guard, errors, readiness, lifecycle, module loader
├── plugins/
│   ├── database.ts           database binding (PostgreSQL here; MongoDB apps get their own)
│   ├── db-prisma/, db-mongoose/
│   ├── redis, cache, queue, events, geo, cloudinary, payment   optional plugins
│   └── index.ts, manifest.ts registry driven by src/framework.manifest.json
├── modules/                  auth, user, health, metrics (+ _template example)
├── experimental/             not shipped, not registered (see its README)
└── scripts/                  build-template.ts (tooling), make-module.ts (shipped)
packages/create-techunico-app/
├── index.js, lib/compose.js  CLI
├── scaffold/                 app-owned files (package.json, README, _gitignore, tests)
├── overlays/mongodb/         the only MongoDB-specific files (enforced by tests)
├── assets/prisma/            synced from prisma/ by build:template
└── template/                 generated by build:template (gitignored, published)
scripts/smoke/pack-smoke.mjs  packaging smoke test
tests/                        unit + integration tests
docs/                         audit, remediation checklist, security advisory
```

`src/framework.manifest.json` is the single source of truth for core packages, database
packages and optional plugins (requirements, npm packages, files). Both the runtime plugin
registry and the CLI read it; tests keep its versions equal to this repository's `package.json`.

## Development

Requires Node.js 20+ and PostgreSQL for running the framework locally.

```bash
npm install
npm run generate:pg          # Prisma client for prisma/schema.postgresql.prisma
cp .env.example .env         # then set DB_PROVIDER=postgresql, DATABASE_URL, JWT_SECRET
npm run dev
```

`JWT_SECRET` must be a random value of at least 32 characters:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

| Command | What it does |
|---|---|
| `npm run typecheck` | `tsc` for the source and the tests |
| `npm test` | Jest unit + Fastify-inject integration tests (no database needed) |
| `npm run build:template` | Builds `packages/create-techunico-app/template` |
| `npm run test:smoke` | Packs the CLI, installs it **outside the repository**, generates PostgreSQL and MongoDB apps with no / all plugins, installs, type-checks, tests, builds, starts them against throwaway databases and checks auth, readiness, metrics protection and graceful shutdown |
| `npm run build` / `npm start` | Compile and run the framework itself |

`test:smoke` starts isolated `postgres`, `mongod` and `redis-server` processes on random ports when
the binaries are installed; in CI it uses service containers (`SMOKE_PG_URL`, `SMOKE_MONGO_URL`,
`SMOKE_REDIS_HOST`). Don't run it at the same time as `npm test`: both rebuild the template.

## Releasing the CLI

1. `npm run typecheck && npm test && npm run test:smoke`
2. Bump `packages/create-techunico-app/package.json` and update its `CHANGELOG.md`
3. `npm run build:template`, then publish from `packages/create-techunico-app`

## Security

- JWT keys come only from configuration; see `src/core/jwt.ts`.
- Existing generated applications must be patched individually — see
  [docs/remediation/SECURITY-ADVISORY.md](docs/remediation/SECURITY-ADVISORY.md).
